1. Giới thiệu dự án Kinderland

Hệ thống thương mại điện tử chuyên bán đồ chơi, sách thiếu nhi, quần áo và học liệu giáo dục cho trẻ em.

Hai nhóm người dùng chính

  • Khách hàng: Duyệt sản phẩm, đánh giá, thêm giỏ, đặt hàng, thanh toán, tích điểm, trả hàng.
  • Admin & Manager: Quản lý sản phẩm/khuyến mãi, đơn hàng, tài chính, nhập/chuyển kho.

Bối cảnh

Được xây dựng ban đầu dạng Modular Monolith, sau đó chuyển đổi (migrate) sang kiến trúc Microservices để tăng khả năng mở rộng và chịu lỗi.

Đích đến
Database per Service.
Triển khai & mở rộng riêng biệt, tăng chịu lỗi cục bộ.
Giữ nguyên contract API với Frontend React.

Thách thức lớn nhất

Phá vỡ coupling FK ở tầng JPA. Thay thế bằng:

Tham chiếu ID lỏng.
Dữ liệu snapshot (Denormalization).
Giao tiếp OpenFeign (Sync).
Sự kiện qua Kafka (Async).

7. Các mẫu thiết kế (Design Patterns)

Database per Service

Mỗi service một CSDL riêng, tách biệt hoàn toàn về dữ liệu.

API Gateway Auth

Loại bỏ header mạo danh từ client, inject X-Auth-Email đáng tin cậy.

Saga (Choreography)

Trừ/hoàn kho bất đồng bộ qua Kafka (OrderCreated → trừ kho).

Idempotency

Bảng ProcessedEvent chống xử lý trùng lặp tin nhắn Kafka.

Denormalization / Snapshot

Lưu ảnh chụp giá/tên sản phẩm lúc đặt hàng để đơn hàng bất biến.

Event-driven Architecture

Giao tiếp lỏng lẻo qua sự kiện, giảm phụ thuộc trực tiếp giữa service.

6 pattern phối hợp cùng nhau để giải quyết bài toán tách rời dữ liệu & giao tiếp giữa các service

9. Các nghiệp vụ chính đã triển khai

Auth & Users

  • Đăng ký/đăng nhập (Local + Google).
  • Refresh token, quên mật khẩu bằng OTP qua email.
  • Đăng xuất thu hồi token (Redis blacklist).
  • Quản lý sổ địa chỉ.

Product & Kho

  • Quản lý biến thể SKU, tồn kho theo cửa hàng.
  • Tìm cửa hàng gần theo toạ độ Haversine.
  • Chuyển kho nội bộ (State Machine).
  • AWS S3 lưu ảnh sản phẩm.

Order & Finance

  • Giỏ hàng, checkout VNPay/COD.
  • Tích lũy và đổi điểm thưởng.
  • Báo cáo doanh thu tài chính.
  • Quy trình trả hàng & hoàn tiền.

Notification

  • Gửi email chào mừng tự động khi người dùng đăng ký mới.
  • Chạy ngầm qua sự kiện Kafka.
  • Không block luồng đăng ký của khách.

11. Bảo mật & Phân quyền

JWT Tập trung

Verify token duy nhất tại API Gateway. Bóc tách payload và truyền xuống downstream dạng X-Auth-Role.

Thu hồi Token

Redis Blacklist với TTL = thời gian sống còn lại của token khi đăng xuất. Cơ chế fail-open nếu Redis gặp sự cố.

Phân quyền Role-based

Customer / Admin / Manager kiểm soát qua @PreAuthorize và GatewayAuthContext.

Điểm mấu chốt: toàn bộ logic xác thực chỉ nằm ở một nơi duy nhất — API Gateway. Các service downstream không cần biết cách verify JWT, chỉ tin tưởng header đã được xác thực.

13. Công nghệ còn thiếu & Hướng phát triển

  • Observability:Cần ELK/Loki (Log), Zipkin/Jaeger (Tracing), Prometheus + Grafana (Metrics).
  • Resilience:Cần Resilience4j — Circuit Breaker, Retry, Bulkhead, Rate Limiter.
  • CI/CD & K8s:Thay thế Docker Compose bằng Kubernetes + Helm, GitHub Actions/Jenkins.
  • Automation Test:Cần JUnit 5 + Mockito, Testcontainers, Pact (contract test).
  • Tính năng:Tích hợp vận chuyển GHN, Elasticsearch tìm kiếm, WebSocket/SSE realtime.

14. Kết luận

Dự án Kinderland minh hoạ trọn vẹn vòng đời chuyển đổi từ Modular Monolith sang Microservices, áp dụng thực tiễn các chuẩn công nghiệp:

Database per Service
API Gateway
Service Discovery
Kafka Saga
Idempotency
Snapshot/Denormalization

Hệ thống đã chạy ổn định end-to-end (Frontend ↔ 6 microservice ↔ Kafka/Redis/PostgreSQL). Đây là nền tảng vững chắc để tiến tới Production bằng cách bổ sung Observability, Resilience, CI/CD và Kubernetes.
